# Audit visual UI & bug interface — Adore Illustratoze

**Prioritas:** hanya UI: rendering, struktur, layout, tab, ikon, warna, overflow dan interaksi antarmuka. **Status:** audit statis, 11 November 2026. **Basis:** kode branch saat ini, base `0bb315e`. Belum ada browser/screenshot di lingkungan ini, jadi gue tidak akan mengaku sudah melihat hasil render atau memastikan seluruh bug visual di semua resolusi. Temuan `[kode]` dibuktikan langsung oleh JSX/CSS/state yang dibaca; `[cek visual]` adalah risiko dari konstruksi kode yang harus direproduksi. Severity: P1 = rusak/menghalangi UI utama, P2 = ketidakrapian/kebingungan signifikan, P3 = polish. Ini audit awal yang lebih dalam, **bukan klaim semua bug sudah ditemukan**.

## 1. Kesimpulan desain visual

Masalah terbesar bukan satu tab saja. UI membentuk beberapa lapis navigasi dan kontrol yang tumpang tindih: header terlalu padat, tab dokumen mencampur nama + ekstensi + zoom + mode, panel punya tab luar **dan** tab dalam, Properties disamakan dengan Info, banyak tool berbagi gambar ikon sama, dan kontrol palet/warna berada di beberapa lokasi. Tampilan default juga menggabungkan komponen dengan CSS theme, Tailwind warna fixed, inline style, emoji, teks singkatan, dan simbol Unicode. Jadi kesan berantakan bukan cuma masalah warna: **hierarki, grouping, keterkaitan label-konten, ukuran, jarak, overflow dan konsistensi komponen** harus direvisi sebagai sistem.

**Koreksi penting atas dokumen sebelumnya:** `LeftToolbar.tsx` memang punya segitiga sub-tool yang bisa diklik (`ai-tool-flyout-corner`, sekitar baris 291). Audit sebelumnya kurang tepat jika memberi kesan hanya klik kanan/hold yang bisa membuka sub-tool. Area segitiga sangat kecil dan berupa `span` di dalam tombol, bukan kontrol keyboard terpisah; masalah discoverability/akses tetap perlu diuji.

## 9. Spesifikasi UI rapi yang diusulkan

1. **Header:** satu bar aplikasi dan satu bar tab; menu dan setting tidak saling berebut; overflow menu untuk ruang sempit. Tab hanya nama + status + close; nama truncate dan tombol tetap kelihatan.
2. **Toolbar:** satu daftar tool yang jelas, kategori/kelompok konsisten, ikon benar-benar berbeda untuk tool berbeda. Toolbar bisa dipindah, susunan bisa diatur sesuai scope; flyout selalu berada dalam viewport; 1 kolom tetap scrollable.
3. **Dock:** satu tab bar per grup, **tanpa tab internal duplikat**. Panel bisa dipindah antargrup, diurutkan, di-float dan dock melalui indikator drop; resize, reset dan simpan layout jelas. Properties dan Info berbeda.
4. **Panel:** header/tab/body/footer konsisten; satu scroll body; kelompok controls dengan alignment label/nilai, empty state dan mixed selection yang jelas. Hapus elemen berulang yang tidak punya peran berbeda.
5. **Dialog/dashboard:** ukuran adaptif dengan footer tetap terlihat; kartu, menu, tabel dan preset tidak terpotong; semua komponen memakai theme/token yang sama.
6. **Visual system:** sepakati grid spacing, type scale, heights, icon family, semantic colors, border/focus/selected dan layering. Terapkan ke seluruh area, bukan hanya mengganti warna header.

## 10. Rencana kerja dan verifikasi UI

- **Batch D — regresi visual:** screenshot baseline pada viewport 1366×768 dan 1920×1080, 100%/200% zoom, 4 tema dan ID/EN. Tambah 1024×768 jika didukung; periksa satu/dua kolom toolbar, panjang nama, banyak tab, setiap preset, expanded/collapsed/floating, semua 24 panel dan 19 modal. Rekam expected/actual, screenshot, browser, viewport, commit dan status fix.

**Kriteria selesai:** tab yang aktif selalu cocok dengan kontennya; tidak ada ekstensi ganda/tombol mati; tidak ada dua bar navigasi untuk panel yang sama; seluruh kontrol utama terlihat atau punya overflow yang disengaja; popover/dialog tidak terpotong di viewport yang didukung; toolbar dan panel bisa diatur sesuai kesepakatan; warna, ikon, jarak dan active state konsisten; tidak ada regresi pada screenshot/state matrix.
